#### P0-1 — خطر XSS شامل + تخزين الجلسة في `localStorage` = استيلاء كامل على الحساب

**الدليل (أرقام مقيسة بدقة):**
| المقياس | القيمة |
|---|---|
| استخدامات `innerHTML` في `js/` | **356** (و**0** في HTML) |
| منها **إسنادات فعليّة** `.innerHTML = ...` | **327** |
| منها **تبني محتوى ديناميكياً** (قالب نصي بمتغيرات أو سلسلة بـ `+`) | **62** |
| وحدات تُطهّر البيانات قبل الإدراج | **وحدة واحدة فقط**: `js/hr.js` (تعرّف `esc()` وتستخدمها **28 مرة**) |
| باقي الوحدات (13 ملفاً) | **بلا أي تطهير** |

> **ملاحظة منهجية مهمة ومنصفة:** المشروع **يعرف النمط الصحيح وطبّقه** — انظر `js/hr.js:24`:
> ```js
> esc(v) { const d = document.createElement('div'); d.textContent = v ?? ''; return d.innerHTML; }
> ```
> المشكلة أن هذا الحل **لم يُعمَّم** خارج وحدة الرواتب. الإصلاح إذاً ليس تعليم المطوّر شيئاً جديداً، بل **ترقية نمط موجود إلى قاعدة عامة مفروضة آلياً**.

**أمثلة حقيقية على مسارات قابلة للاستغلال** (بيانات من الخادم تُدرج خاماً بلا تهريب):
```js
// js/accounting.js:50 — اسم العميل القادم من قاعدة البيانات يُبنى في HTML مباشرة
dl.innerHTML = (cRes.data || []).map(c => `<option value="${c.name}">${c.phone ? 'هاتف: ' + c.phone : ''}</option>`).join('');

// js/accounting.js:59 — نفس النمط مع اسم المورد
// js/accounting.js:114 — حقل عرض عام يُدرج بلا تهريب
// js/auth.js:417 — نص رسالة الخادم يُدرج في صندوق الخطأ
errorBox.innerHTML = `<strong>⚠️ تنبيه أمان صارم:</strong><br>${data.message}`;
```
- والتوكن يُخزَّن في `localStorage`: `js/auth.js:482` → `localStorage.setItem('rawasi_token', this.token)`.

**لماذا هذا خطير تحديداً هنا؟** النظام يُدخل بيانات نصية عربية حرة من مستخدمين مختلفي الصلاحيات (أسماء عملاء، موردين، بنود عقود، ملاحظات مالية، مرفقات). أي مستخدم بصلاحية `create` يستطيع كتابة `<img src=x onerror=...>` في اسم عميل، فيُنفَّذ في متصفح **المدير العام** عند فتح الشاشة → قراءة `localStorage` → سرقة التوكن → سيطرة كاملة على النظام المالي. هذا هو **OWASP A03: Injection** و**A07: Auth Failures** معاً، وهو المسار الأكثر واقعية لاختراق هذا النظام.

#### P0-2 — لا توجد رؤوس أمان إطلاقاً (مُتحقَّق منه عبر HTTP)

**الدليل — ناتج طلب حقيقي على الخادم العامل:**
```
$ curl -sI http://127.0.0.1:5500/api/health
HTTP/1.1 200 OK
X-Powered-By: Express
Access-Control-Allow-Credentials: true
Content-Type: application/json; charset=utf-8
```
**الغائب كلياً:** `Content-Security-Policy`، `X-Frame-Options`، `Strict-Transport-Security`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`. و`X-Powered-By: Express` مكشوف يكشف التقنية (تسهيل استهداف ثغرات نسخة معروفة).
`grep helmet` → **لا نتائج** في المستودع كله.

**الأثر:** قابلية تضمين النظام في `iframe` خارجي (Clickjacking) لإيهام موظف بالنقر على زر "تحويل" أو "حذف"؛ وغياب منع تخمين نوع المحتوى (MIME sniffing)؛ وكشف بصمة التقنية.

**الحل (سطران + سياسة):**
```bash
npm i helmet
```
```js
const helmet = require('helmet');
app.disable('x-powered-by');
app.use(helmet({
  contentSecurityPolicy: {                       // مرحلة أولى: تقرير فقط
    useDefaults: true,
    directives: {
      'default-src': ["'self'"],
      'img-src': ["'self'", 'data:', 'blob:'],
      'object-src': ["'none'"],
      'frame-ancestors': ["'none'"],
      'base-uri': ["'none'"]
    },
    reportOnly: true
  },
  hsts: { maxAge: 31536000, includeSubDomains: true, preload: true },
  referrerPolicy: { policy: 'strict-origin-when-cross-origin' }
}));
```

#### P0-3 — تسريب بنية النظام عبر رسائل الأخطاء الداخلية + غياب معالج أخطاء مركزي

**الدليل (أرقام دقيقة):**
- `message: err.message` داخل ردود الـ API → **128 موضعاً**.
- `res.status(500)` → **241 موضعاً**، مع `try/catch` مُكرّر يدوياً في كل مسار (52 مرة في `project_management.js` وحده!).
- `grep "app.use((err"` في `server.js` → **لا نتائج**: لا يوجد معالج أخطاء مركزي.

**الأثر:** تسريب أسماء جداول وأعمدة ومسارات ملفات ونصوص SQL للمهاجم (Information Disclosure)، وصعوبة تتبع الأخطاء في الإنتاج، وتكرار كود ضخم. مثال واقعي: فشل `INSERT` يعيد للمستخدم رسالة محرك قاعدة البيانات بأسماء الأعمدة الحقيقية.

**الحل:**
```js
// server/middleware/errors.js
class AppError extends Error {
  constructor(status, code, message, details) {
    super(message);
    this.status = status; this.code = code; this.details = details;
    this.expected = true;
  }
}
const notFound = (req, res) => res.status(404).json({ type:'about:blank', title:'غير موجود', status:404, detail:req.originalUrl });
const errorHandler = (err, req, res, _next) => {
  const status = err.status || 500;
  req.log?.[status >= 500 ? 'error' : 'warn']({ err, reqId: req.id }, err.message);
  res.status(status).json({
    type: `https://api.rawasi-aden/errors/${err.code || 'internal'}`,
    title: err.expected ? err.message : 'خطأ داخلي في الخادم',
    status,
    detail: err.expected ? err.details : undefined,   // لا تسريب أبداً للتشغيل غير المتوقع
    requestId: req.id
  });
};
```
```js
// server.js — بعد كل المسارات
app.use('/api/*', notFound);
app.use(errorHandler);
// وفي كل مسار لاحقاً:  catch (err) { next(err); }   بدل res.status(500).json({message: err.message})
```
> جرّب أيضاً `express-async-errors` أو غلاف `asyncHandler` لتجنّب `try/catch` المتكرر في 286 نقطة نهاية.

## 8) خلاصة الحكم الهندسي

**التشخيص:** لديك **نظام أعمال من الدرجة الأولى** مبني على **قشرة تقنية من الدرجة الثانية**. المنطق المحاسبي والهندسي مغطّى بشكل يندر في السوق المحلي (قيود مزدوجة، إقفال فترات، تكلفة مشاريع بـ EVM، ضرائب وضمانات، تعهّدات وصناديق، رقابة مالية داخلية — 15 خدمة أعمال تختبر تلقائياً في 8.5 ثانية). هذه ميزة تنافسية حقيقية.

**الخطر الأكبر ليس الأداء، بل الأمن:** نظام بهذا الحساسية يجمع بين **327 إسناداً مباشراً لـ `innerHTML`** (62 منها تبني محتوى ديناميكياً، والتطهير موجودة في وحدة واحدة فقط من 14)، و**توكن مخزّن في `localStorage`**، و**رؤوس أمان غائبة**، و**سر منشور يمكن تشغيله عبر نفق عام**، ولديه **صفر اختبار واجهة**. هذه تركيبة تُنتج اختراقاً وليس احتمالاً نظرياً.

**القاعدة الموصى بها:** لا تعد كتابة النواة. نفّذ P0 خلال أسبوعين (تكلفتها الإجمالية ~10 أيام عمل وتلغّي الأخطر كلياً)، ثم رحّل الواجهة تدريجياً بـ *Strangler Pattern*، ثم اجعل النشر حتمياً بالحاويات. عند الوصول إلى المرحلة 3 سيكون هذا النظام بمستوى منتج تجاري قابل للبيع متعدد المنشآت — لا مجرد نظام داخلي لشركة واحدة.
